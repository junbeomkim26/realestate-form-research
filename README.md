# 부동산 매물 등록폼 현장조사

직방 · 다방 · 당근부동산 **매물 등록폼의 DOM 구조를 실제로 눌러 가며 조사한 결과**와,
그 조사에 쓴 도구, 그리고 조사 결과로 되살린 재현본입니다.

자동입력(폼 자동 채우기)을 만들려면 **무엇을 어떤 순서로 붙잡아야 하는지**가 필요합니다.
화면 캡처 한 장이나 초기 HTML 만으로는 그걸 알 수 없습니다. 예를 들어 **당근은 칸 124개 중
80개(65%)가 처음엔 화면에 없고**, 가격 칸은 거래 유형을 체크해야 비로소 생깁니다.
그래서 직접 조작하면서 DOM 이 어떻게 변하는지를 기록했습니다.

## 무엇이 들어 있나

```
├── captures/2026-09-08-현장수집/
│   ├── 직방/DOM-전수조사.md        ← 핵심 결과물
│   ├── 다방/DOM-전수조사.md
│   └── 당근부동산/DOM-전수조사.md
├── docs/여러-플랫폼에-한-번에-넣기.md  세 문서를 가로로 자른 대조 노트
├── tools/필드로그/                  DOM 과 조작 흐름을 기록하는 크롬 확장 (v2.0.0 — 낡음)
└── 재현/                            죽은 스냅샷을 눌러볼 수 있게 되살리는 스크립트
```

### 1. `captures/` — 조사 결과 (이 저장소의 핵심)

플랫폼별 `DOM-전수조사.md` 한 편씩. 각각 이렇게 구성돼 있습니다.

| 절 | 내용 |
|---|---|
| 근거와 한계 | 무엇으로 확인했고 **무엇을 확인하지 못했는지** |
| 화면 위→아래 골격 | 폼 전체를 순서대로 |
| 컨트롤별 마크업과 조작법 | 체크박스·드롭다운·달력이 실제로 어떻게 생겼고 어떻게 눌러야 하는지 |
| **셀렉터 안정성 등급** | 무엇을 붙잡아야 하고 무엇을 붙잡으면 안 되는지 |
| **조건부 표시 그래프** | 무엇을 누르면 무엇이 나타나는지 |
| 선택지 카탈로그 | 드롭다운·라디오의 값 전수 |
| 자동화 체크리스트 | 구현할 때 걸릴 함정 |
| 다시 캡처해야 아는 것 | 남은 빈칸 |

**모든 인과 주장에 조작 id(`[a17]`)와 초 단위 시각이 붙어 있습니다.** 원본 기록에서 되짚을 수 있게요.

> ⚠ **원본 수집 데이터(JSON·HTML·PNG)는 이 저장소에 없습니다.** 중개사무소 계정 정보와
> 실제 취급 매물 주소가 담겨 있어 제외했습니다(`.gitignore` 참조).
> `captures/` 아래 폴더에 문서만 있고 데이터가 없는 것은 그 때문입니다.

세 플랫폼이 **기술적으로 완전히 다릅니다.**

| | 당근 | 직방 | 다방 |
|---|---|---|---|
| 기반 | React + seed | Radix(shadcn) + react-hook-form | styled-components |
| `<form>` | 없음 | 있음 | 이름칸 1개만 감쌈 |
| `<select>` | **0개** | 15개(숨은 미러) | **12개 (진짜)** |
| 1순위 셀렉터 | `name` | 의미 있는 `id` | **표의 행 제목 텍스트** |
| 상태 읽기 | `input.checked` | `aria-checked` / **클래스** | `input.checked` |

### 2. `docs/여러-플랫폼에-한-번에-넣기.md` — 세 문서를 가로로 자른 대조 노트

플랫폼 문서 세 편이 세로(한 플랫폼을 끝까지)라면, 이건 가로다.
**매물 값 하나가 세 곳에 각각 어떤 이름·단위·형식으로 들어가는지**를 맞춰 놓았습니다.

같은 값인데 세 곳이 어긋나는 지점이 많습니다. 예를 들어

- **직방은 한 폼 안에서 보증금은 「만원」, 관리비 정액 금액은 「원」** 입니다
- 방향 코드가 `S` / `SOUTH` / `남향` 으로 다르고, **화면에 놓인 순서까지 셋 다 다릅니다**
  (인덱스로 고르면 남동과 북서가 뒤바뀝니다)
- **당근만 거래 유형을 복수로 고를 수 있고**, 직방 원룸 폼에는 「매매」가 아예 없습니다
- **직방 주소 칸의 `name` 은 `lat`** 입니다. 위도가 아니라 주소 문자열이 들어갑니다

[`docs/여러-플랫폼에-한-번에-넣기.md`](docs/여러-플랫폼에-한-번에-넣기.md)

### 3. `tools/필드로그/` — 수집 도구

아무 http/https 사이트에서 **폼의 DOM 상태와 조작 흐름을 기록하는 크롬 확장**입니다.
특정 플랫폼에 묶여 있지 않습니다.

> ⚠ **여기 담긴 사본은 v2.0.0 입니다 — 새 수집에 쓰지 마세요.**
> 2026-09-08 회차에 쓴 그 버전이고, 세션 뒷부분의 DOM 변화가 조용히 사라지는 결함이
> 그대로 있습니다(2.2.0 에서 고쳐졌으나 그 버전은 여기 없습니다).
> 이 사본은 **그 회차 기록을 읽는 데 필요한 근거**로 남겨 둔 것입니다.
> 자세한 건 [`tools/필드로그/README.md`](tools/필드로그/README.md) 맨 위.

- 압축해제 로드(Load unpacked) 전용. 웹스토어에 올리지 않았습니다
- 네트워크 전송 코드가 없습니다. 기록은 그 PC 의 크롬 저장소에 있다가 JSON 으로 내려받습니다
- 사용법: [`tools/필드로그/README.md`](tools/필드로그/README.md)

그 README 에는 **이 도구로 수집하면서 드러난 문제 9가지**도 적혀 있습니다.
(변이 기록이 앞부분만 남는 것, 인과 기록이 실제 원인과 어긋나는 경우 등)
**수집 결과를 다시 분석할 사람은 먼저 읽어 주세요.**

### 4. `재현/` — 눌러볼 수 있는 재현본

SingleFile 로 저장한 폼 스냅샷은 `<script>` 가 전부 제거돼 **완전히 죽어 있습니다.**
드롭다운을 눌러도 열리지 않습니다. 여기에 **조사로 확인한 동작만** 다시 얹습니다.

```bash
python3 재현/직방/build.py     # 그리고 만들어진 html 을 더블클릭
```

> **단, 원본 스냅샷이 있어야 빌드됩니다.** 그 스냅샷은 위와 같은 이유로 이 저장소에 없습니다.
> 즉 **`재현/` 은 지금 그대로는 실행되지 않습니다.** 스크립트와 방법을 공개하는 것이고,
> 자기 환경에서 직접 수집한 스냅샷이 있으면 같은 방식으로 되살릴 수 있습니다.

재현본은 **원본에 없는 식별자를 만들어내지 않도록 감사**했습니다. 정적·런타임 두 단계로
`name`·`id`·`role` 을 전수 대조해 **추가 0건**을 확인했고, 재현본만 갖는 것은 `data-flr*` 접두사
셋뿐입니다. 자세한 내용은 [`재현/README.md`](재현/README.md) 「감사」 절에 있습니다.
